SATP pipeline: from scraped incidents to coded events

From the South Asia Terrorism Portal summaries (2000 to 2025) to one row per conflict event with an action type, actors and a 2001 district unit. Scripts in code/ and, where marked, code/sandbox/; files in scraped_data/ (git-ignored). Units come from the Irrigating Peace pipeline.

code/split_multi_incident_entries.R

  1. Flag. An entry with two or more sentences is flagged if it has at least 900 characters, two different written-out dates, or a cue phrase ("in another incident", "separate encounter", "a series of"). 39,804 entries (31.2%).
  2. Ask DeepSeek. Each flagged entry goes out as numbered sentences. DeepSeek labels every sentence as part of a main incident (a specific act at one place and time) or as context (background, earlier acts, follow-ups, statements, legal steps). It returns sentence numbers only, so event texts are the original words.
  3. Attach context. Each context sentence joins the main incident closest to it by position; ties go to the earlier one. An entry with no main incident stays whole.
  4. Build events. One row per incident, with the incident's date when the text states it. Unflagged entries become one event unchanged.
  5. Answers are cached by entry and prompt version, so a rerun pays only for new entries; 24 requests run at once.
→

code/code_events_deepseek.R

  1. Sends each distinct event text with the coding rules of the SATP manual.
  2. DeepSeek returns is_event (policy news, statements, strike calls and court cases are not events), the action flags, the actor and its type (State forces or Rebel group, only when the text names one), the target type, fatalities and injuries, how many of each were civilians, security forces or militants (government officials and informers count as civilians), the number of people arrested, successful (false for foiled or defused attempts, which still count) and n_incidents.
  3. Derives the ACLED-style event_type and sub_event_type from the flags, in the priority order of the schema.
  4. Answers are cached by a hash of the text and the prompt version (now 4); the console prints tokens and cost after every batch.
  5. The environment variable SATP_TEST_FILE points the script at another file with an event_text column; its texts are coded into separate _test cache and output files.

code/match_event_districts.R

  1. Names. The text becomes words; every run of one to five words, joined without spaces, is looked up in the alias table. Longer names win.
  2. Shared names (Aurangabad, Bijapur) resolve when the text names exactly one of their states, otherwise by the states of the event's SATP series; a name still shared stays ambiguous.
  3. Output per event. The primary unit (the first "X district" mention, else the first resolved name), all units mentioned, the state mentioned. Events naming only a state keep no unit.
  4. Scoring. The same matching runs on the hand-coded incidents and is compared with the unit of the hand-coded district name and with the unit containing the hand-coded coordinates.

code/sandbox/export_acled_style.R

  1. One row per event: the 31 ACLED columns in ACLED's order, then the SATP columns (unit_id, the seven action flags, the confidence).
  2. event_type and sub_event_type come from the DistilBERT flags (probability above 0.5), first match in the order abduction, bombing, armed assault, infrastructure, arrest, seizure, surrender.   4. event_confidence is the highest of the seven DistilBERT probabilities.

code/sandbox/senna_district_crosscheck.R

  1. Splits each summary into sentences and tags them with SENNA: verbs with their arguments, and place names (tag LOC).
  2. A sentence is an event candidate if a verb from the list has an object (role A1), as in Fetzer's definition.
  3. Location entities of candidate sentences are matched to districts, with the same names and aliases as the baseline. A shared name counts only if a state named in the text resolves it.
  4. An incident's district is the first candidate sentence with a match. Scores it against the hand-coded district.

How each step works

1. An entry becomes one event per main incident

Context sentences stay with the main incident nearest to them. Illustrative entry of five sentences.

ChosenDeepSeek labels sentences and returns numbers, so every event text is a set of the original sentences, and wrong answers (a missing or repeated sentence) are caught and kept as one event.
Alternative consideredAsking DeepSeek to write each incident's text. It can reword, drop or invent details, and nothing checks it against the entry.

2. The old model's confidence decides which events DeepSeek must check

About a third of entries are not violent acts (speeches, policy, court rulings), and the old model has no "not an event" answer. Its top probability separates the clear cases; the middle goes to DeepSeek. Shares of all 131,029 events; sample of 2,497 events DeepSeek coded.

PlannedAccept above 0.9, reject at 0.3 or below, and send the middle zone to code_events_deepseek.R, which also returns actors, targets and counts for those events.
Alternative considered"At least one flag" as the event indicator: it keeps 98% of DeepSeek's events but also 33% of its non-events.

3. A place name in the text becomes a unit

Longest names are claimed first; a name shared by districts in several states is resolved in a fixed order.

ChosenAlias table of the Irrigating Peace pipeline: the match returns the unit directly, with 2001 boundaries, and districts created after 2001 point to their 2001 parent.
Alternative consideredMatching GADM district names and mapping to units afterwards, which loses spellings and the post-2001 parents.

Event definition

ItemRule
EntryOne row of scraped_incidents: a unique date and summary text, incident_uid.
EventOne incident of an entry: event_uid (a row number, renumbered whenever the splitter reruns), event_part within its entry, event_text made of the entry's original sentences.
Event vs non-eventAn event is a specific violent act or security operation that took place; announcements, speeches, strike calls and court proceedings are not (SATP coding manual).
ActionsArmed assault, abduction, bombing, infrastructure, surrender, arrest, seizure; an event can have several. A planted device that is found or fails to go off still counts as a bombing.
ActorCoded only when the text identifies one: State forces or Rebel group (including unidentified militants); empty otherwise.
Casualties and arrestsFatalities and injuries as reported in the text, and how many of each were civilians (including government officials and informers), security forces or militants; victims whose group the text does not state count only in the total. Arrested: people arrested or detained, not those who surrendered.
Unit2001 census district (unit_id, 584 units) from the Irrigating Peace pipeline.
